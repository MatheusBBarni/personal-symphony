# ADR-005: Keep PR handoff independent of tracker kind

## Status

Accepted

## Date

2026-05-08

## Context

The PRD excludes replacing GitHub functionality and changing Task Branch, Stage Push, or packaged behavior. Existing pull request handoff behavior depends on repository and branch state rather than issue tracking alone, but parts of the current implementation read GitHub tracker fields for repository naming.

The user selected keeping pull request handoff behavior independent of tracker kind. When a minibeads task reaches the same handoff points, Symphony should update the local task status in minibeads.

## Decision

V1 will keep existing pull request handoff behavior available when configured, independent of whether the selected Issue Tracker is GitHub or minibeads.

For minibeads runs, tracker status transitions still write back through the minibeads adapter when Symphony reaches dispatch, review, success, retry, Human Attention Status, or Merge Attention Status states. Pull request handoff must not require GitHub Issues or GitHub Projects, but it may continue using the repository’s git remote and existing PR handoff settings.

## Alternatives Considered

### Alternative 1: Disable PR handoff for minibeads V1

- **Description**: Require pull request handoff features to be off for local tracker runs.
- **Pros**: Simplifies V1 and avoids hidden GitHub assumptions.
- **Cons**: Artificially weakens parity for users who use local issues but still want PR handoff.
- **Why rejected**: The user selected tracker-independent PR handoff.

### Alternative 2: Require separate GitHub remote settings

- **Description**: Only allow PR handoff for minibeads when explicit remote/owner/repo settings are configured outside the tracker.
- **Pros**: Makes remote dependency explicit.
- **Cons**: Adds configuration burden and may be unnecessary when current git remote behavior is sufficient.
- **Why rejected**: V1 should preserve existing PR handoff behavior where possible rather than introduce a new configuration model.

## Consequences

### Positive

- Local issue users can still use existing branch and pull request workflows.
- Pull request behavior remains a git/review handoff concern, not an Issue Tracker concern.
- minibeads task status remains in sync with Symphony stage transitions.

### Negative

- Existing PR handoff code must be reviewed for GitHub tracker field assumptions.
- Documentation must distinguish GitHub as an Issue Tracker from GitHub as a possible remote PR destination.

### Risks

- **Hidden coupling to tracker.owner/repo**: Mitigate by deriving PR repository context from existing PR settings or git remote behavior instead of Issue Tracker fields when minibeads is selected.
- **Status drift after PR handoff failure**: Mitigate by using existing retry/attention status transitions through the selected tracker.

## Implementation Notes

- Do not require GitHub Issues, GitHub Projects, or tracker token configuration for minibeads PR handoff.
- Preserve non-force push behavior.
- Update minibeads status through the same selected tracker status path used by normal stage transitions.
