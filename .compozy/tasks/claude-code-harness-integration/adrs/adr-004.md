# ADR-004: Provider-Neutral Runtime State and Claude Stream Events

## Status

Accepted

## Date

2026-05-08

## Context

Runtime State currently exposes aggregate token usage under `codex_totals`, and frontend live-state types consume that name directly. Running task rows expose the Stage Agent, but not the selected Harness name or kind. Claude Code V1 uses CLI `stream-json`, which can carry live messages and tool events that are more structured than the current raw stdout/stderr token scanner.

The PRD requires operators to identify which Harness was selected and avoid Codex-specific confusion in mixed-Harness runs.

## Decision

Runtime State will rename `codex_totals` to provider-neutral `usage_totals` as part of this feature. The frontend and tests will update in the same change.

Running task state will expose selected Harness identity, including at least Harness name and kind.

Claude `stream-json` output will be parsed for live messages and tool events into Runtime State rows for dashboard display. Full raw output remains in stdout/stderr files for diagnostics.

## Alternatives Considered

### Alternative 1: Keep `codex_totals` As Deprecated Alias

- **Description**: Add `usage_totals` while keeping `codex_totals` for compatibility.
- **Pros**: Minimizes frontend/API compatibility risk.
- **Cons**: Keeps Codex-specific language in the Runtime State model and extends ambiguity.
- **Why rejected**: The user selected an immediate rename to `usage_totals`.

### Alternative 2: Parse Only Claude Usage Totals

- **Description**: Extract token or usage totals from Claude stream events while leaving live messages and tools only in logs.
- **Pros**: Smaller backend change.
- **Cons**: Fails the operator need for live Harness-specific visibility when Claude is selected.
- **Why rejected**: The selected V1 scope should surface Claude live messages and tool events in Runtime State rows.

### Alternative 3: Store Raw Stream Events In Runtime State

- **Description**: Copy raw `stream-json` events directly into Runtime State for later frontend rendering.
- **Pros**: Preserves source detail.
- **Cons**: Bloats Runtime State and couples dashboard shape to provider event formats.
- **Why rejected**: Runtime State should expose normalized live task information and leave raw provider logs in stdout/stderr diagnostics.

## Consequences

### Positive

- Runtime State language matches mixed-Harness execution.
- Operators can see selected Harness identity during running tasks.
- Claude runs can show useful live progress beyond token totals.

### Negative

- Renaming `codex_totals` is a breaking snapshot shape change for any consumer expecting the old field.
- Claude stream parsing introduces provider-specific normalization logic.

### Risks

- **Frontend drift**: ReScript types and live-state tests must update with the backend snapshot. Mitigation: update frontend tests with representative snapshots.
- **Provider event shape changes**: Claude stream-json may evolve. Mitigation: parse defensively and keep raw logs as the durable diagnostic source.

## Implementation Notes

- Rename backend Runtime State field and JSON key from `codex_totals` to `usage_totals`.
- Update frontend ReScript types and dashboard snapshot derivation.
- Add `harness_name` and `harness_kind` to running task JSON.
- Normalize Claude stream-json events into running row last message / last event / tool activity fields.
- Do not store unbounded raw stream events in Runtime State.
