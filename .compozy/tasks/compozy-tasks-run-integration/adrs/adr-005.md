# ADR-005: Relaunch task steps sequentially in one worktree

## Status

Accepted

## Date

2026-05-08

## Context

The PRD requires all task files in one Compozy PRD run to execute in the same **Agent Worktree** and **Task Branch**. Each task-step prompt must include the current `task_NN.md` file plus `_prd.md` and `_techspec.md` when those artifacts exist.

The main implementation choice is whether Symphony should launch one long agent prompt for all task files, delegate to `compozy tasks run`, or relaunch one task step at a time while preserving the same worktree and branch.

## Decision

V1 will execute Compozy task steps by sequential relaunch.

After one task step completes, Symphony updates the corresponding task file frontmatter, selects the next pending task file, and launches the next task-step prompt in the same **Agent Worktree** and **Task Branch**. Final PRD-run completion happens only after the last selected task step completes or no runnable task steps remain.

Intermediate task-step completion must not trigger final Task Branch integration or cleanup. The existing final completion path should run only when the PRD run is complete.

## Alternatives Considered

### Alternative 1: Single long prompt

- **Description**: Launch one agent once with all task files, PRD, and TechSpec in one prompt.
- **Pros**: Minimal orchestration changes and no per-step relaunch loop.
- **Cons**: Less observable progress, harder retries, larger prompt context, and weaker task-step status persistence.
- **Why rejected**: The PRD requires visible progress and per-step execution state.

### Alternative 2: Delegate to `compozy tasks run`

- **Description**: Invoke Compozy's own task runner inside the Agent Worktree.
- **Pros**: Reuses Compozy task execution behavior.
- **Cons**: Blurs Symphony's orchestration responsibilities, reduces control over Agent Worktree lifecycle, and complicates Runtime State integration.
- **Why rejected**: V1 treats Compozy task files as tracker artifacts, not a replacement execution engine.

## Consequences

### Positive

- Each task-step prompt stays scoped and inspectable.
- Retry, progress, and attention handling can operate at task-step granularity.
- The PRD run preserves one worktree and branch across all steps.

### Negative

- Orchestrator completion needs a Compozy-specific intermediate completion path.
- Runtime State needs enough progress projection to explain which task step is active.
- Long PRD runs may involve multiple agent launches within the same worktree.

### Risks

- Incorrect final-completion detection could integrate or clean up the Task Branch too early.
- A failed intermediate step must not leave the PRD run in a contradictory running state.

## Implementation Notes

- Keep the task-step selection deterministic by sorting `task_NN.md` files by numeric suffix.
- Include the current task file, `_prd.md`, and `_techspec.md` in every task-step prompt.
- Preserve existing final Stage Commit, Stage Push, and Task Branch Integration semantics at PRD-run completion.
