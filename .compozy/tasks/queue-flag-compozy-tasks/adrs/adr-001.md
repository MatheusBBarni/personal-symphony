# ADR-001: Compozy Queue Slug Scope

## Status

Accepted

## Date

2026-05-13

## Context

Personal Symphony already supports an **Ordered Queue** through `--queue`, and current Compozy-backed selector flows use the canonical `compozy:<slug>` identifier for a **Compozy PRD Run**. A solo operator running a Workspace Repository with `tracker.kind = "compozy_tasks"` naturally thinks in terms of `.compozy/tasks/<slug>/` directory names and wants to run:

```sh
symphony --queue queue-flag-with-compozy-tasks,claude-code-harness-integration
```

The product tension is that bare Compozy slugs are ergonomic in Compozy tracker mode, but they are not generic Workspace Repository issue identifiers. Interpreting bare slugs too early would leak Compozy-specific meaning into the generic **Ordered Queue** parser and could create ambiguity for GitHub or minibeads tracker modes.

## Decision

V1 will support bare Compozy PRD Run slugs for `--queue` only when the selected Issue Tracker is `compozy_tasks`. The accepted input is a comma-separated list of bare slugs, and each slug normalizes to the existing canonical `compozy:<slug>` identifier before dispatch.

Validation is all-or-nothing. If any supplied slug is malformed, missing, terminal, or not dispatchable, Symphony rejects the entire **Ordered Queue** before any task dispatch, Agent Worktree creation, Task Branch creation, or tracker status mutation.

Existing selector forms remain valid. GitHub numeric selectors, minibeads selectors, and canonical `compozy:<slug>` selectors keep their current behavior.

## Alternatives Considered

### Alternative 1: Require Canonical `compozy:<slug>` Selectors Only

- **Description**: Keep the current behavior and require operators to pass `--queue compozy:<slug>,compozy:<slug>`.
- **Pros**: No ambiguity, no additional tracker-aware normalization.
- **Cons**: Forces a solo operator to translate known Compozy PRD Run directory names into a prefixed selector form every time.
- **Why rejected**: It preserves correctness but leaves the requested workflow friction unresolved.

### Alternative 2: Accept Bare Slugs In Generic Ordered Queue Parsing

- **Description**: Teach the generic **Ordered Queue** parser to accept unprefixed non-numeric tokens as Compozy PRD Run slugs.
- **Pros**: Earliest parse-time feedback and a simple implementation surface for the CLI flag.
- **Cons**: Couples a generic product-level queue abstraction to Compozy-specific selector semantics.
- **Why rejected**: Bare slugs only have meaning after Runtime Settings select the Compozy-backed Issue Tracker.

### Alternative 3: Partially Enqueue Valid Slugs

- **Description**: Enqueue valid Compozy PRD Run slugs and skip invalid ones with diagnostics.
- **Pros**: Allows valid work to start even when one input entry is wrong.
- **Cons**: Makes operator intent ambiguous and complicates exit status, skipped-entry reporting, and rerun behavior.
- **Why rejected**: The user selected fail-fast behavior, and V1 should keep queue acceptance transactional.

## Consequences

### Positive

- Solo operators can queue known Compozy PRD Runs without manually adding `compozy:` prefixes.
- The generic **Ordered Queue** concept remains intact across tracker kinds.
- Existing GitHub, minibeads, and canonical Compozy selector behavior remains compatible.
- Invalid queue input fails before runtime side effects begin.

### Negative

- The same bare token is valid in Compozy tracker mode and invalid in other tracker modes, so diagnostics must clearly explain the active tracker context.
- Implementation needs a tracker-aware normalization step after Runtime Settings load, not just a pure CLI parse change.

### Risks

- Users may expect bare selectors to work for other tracker kinds. Mitigation: document bare slugs as a `compozy_tasks`-only affordance.
- Poor diagnostics could make fail-fast behavior frustrating. Mitigation: report every invalid slug and distinguish malformed, missing, terminal, and not-dispatchable cases.

## Implementation Notes

- Preserve canonical `compozy:<slug>` identifiers in Runtime State, persisted Ordered Queue state, Task Branch naming, and tracker lookup.
- Keep current root validation and Workspace Repository behavior unchanged.
- Do not change Runtime Contract defaults.
