# ADR-004: Evidence Command Completion Gate

## Status

Accepted

## Date

2026-05-20

## Context

The PRD requires **Goal met** to be backed by deterministic evidence. Today, an agent child that exits with code `0` proceeds into existing completion behavior, including Stage Commit and status handling. That path is too trusting for Evidence-First Goal Loop semantics.

The user selected a configured evidence command as the V1 source of deterministic evidence. The command should receive structured JSON on stdin plus a temp-file path environment variable, matching existing Context Command conventions.

The user also selected a bounded retry policy: if evidence is missing or the command fails, Symphony should retry the same task with missing-evidence guidance until the configured retry limit is exhausted, then move the task to Human Attention.

## Decision

Goal Loop completion will be gated by a stage-scoped evidence command before existing completion behavior runs.

On agent exit `0`, a Goal Loop-enabled stage must run the configured evidence command from the Agent Worktree context. The command receives structured JSON on stdin and the same JSON through a temp-file path environment variable. A successful evidence command exits `0` and emits a bounded summary that can be stored as the latest evidence.

If the evidence command succeeds, the Goal Loop records **Goal met** and allows the existing completion path to continue. If the command is missing, times out, exits non-zero, or produces invalid evidence, Symphony retries the same task with missing-evidence guidance while the configured retry limit remains available. After retry exhaustion, Symphony records **Needs attention** and moves the task to Human Attention before Stage Commit or status changes.

## Alternatives Considered

### Alternative 1: Agent exit plus changed files

- **Description**: Treat a successful agent exit and workspace changes as deterministic evidence.
- **Pros**: Low friction; avoids new command configuration.
- **Cons**: File changes do not prove the goal is met; false-completion risk remains high.
- **Why rejected**: It does not satisfy evidence-first completion.

### Alternative 2: Read-only reviewer pass

- **Description**: Run an evaluator or reviewer before completion.
- **Pros**: Can handle richer semantic judgments.
- **Cons**: Independent completion review is explicitly out of V1 scope; model judgment alone is not deterministic evidence.
- **Why rejected**: The PRD requires deterministic evidence and keeps completion review for a separate ADR.

### Alternative 3: Allow completion and mark loop failed

- **Description**: Record evidence failure but allow current completion behavior to continue.
- **Pros**: Preserves current lifecycle behavior most closely.
- **Cons**: Lets unverified work complete despite the Goal Loop saying evidence is missing.
- **Why rejected**: It violates the PRD's core trust requirement.

## Consequences

### Positive

- **Goal met** cannot bypass deterministic evidence.
- Missing evidence receives normal retry opportunity before Human Attention.
- Existing completion behavior remains authoritative after evidence succeeds.

### Negative

- Goal Loop-enabled stages require an evidence command to complete successfully.
- Misconfigured evidence commands can increase retries and attention outcomes.
- The orchestrator completion path needs a new gate before Stage Commit/status behavior.

### Risks

- **Retry loops without new evidence**: Mitigate by adding missing-evidence guidance to the next attempt and respecting the configured retry limit.
- **Command output leakage**: Mitigate with bounded stdout summaries, stderr diagnostics, and existing secret redaction patterns.
- **Ambiguous command contracts**: Mitigate by documenting the evidence input and output expectations in Runtime Settings docs and tests.

## Implementation Notes

- Follow Context Command conventions for structured input, temp-file path environment variable, timeout, bounded output, and diagnostics.
- The TechSpec should define the input schema and state transitions without prescribing command implementation internals.
- Evidence failure must gate before `mark_completed` proceeds into Stage Commit or status updates.
