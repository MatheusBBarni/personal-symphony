# ADR-006: Verify with Focused Alcotest and Backend Build

## Status

Accepted

## Date

2026-05-23

## Context

The implementation touches backend Terminal Console behavior, projection semantics, and key handling. Backend rules require focused Alcotest coverage for Terminal Console behavior changes, and compile-surface changes should run the backend build.

## Decision

Verification will require focused Alcotest coverage for projection, tab visibility, inspect toggling, inline detail rendering, Queue compatibility, Logs exclusion, and read-only behavior. Verification will also require the backend build.

## Alternatives Considered

### Alternative 1: Focused Alcotest Only

- **Description**: Add and run targeted tests without a build command.
- **Pros**: Fastest validation loop.
- **Cons**: Misses broader compile-surface issues from shared type changes.
- **Why rejected**: The projection type and TUI shell compile surface are likely to change.

### Alternative 2: Full Backend Test Suite Plus Backend Build

- **Description**: Require `pnpm test` and `pnpm backend:build`.
- **Pros**: Strongest local confidence.
- **Cons**: Slower than needed for planning and may exceed the narrow change surface.
- **Why rejected**: The TechSpec should require focused validation plus compile verification; full suite can remain a stronger optional gate if implementation risk grows.

## Consequences

### Positive

- Tests cover the changed behavior directly.
- Backend build catches type and module integration issues.

### Negative

- Verification is heavier than focused tests alone.

### Risks

- Focused tests could miss unrelated regressions. Mitigation: escalate to full `pnpm test` if implementation touches runtime orchestration or shared runtime state beyond projection.

## Implementation Notes

- Add tests near existing Terminal Console projection and TUI cases in `apps/backend/test/test_backend.ml`.
- Run the focused Alcotest command for the affected test binary or test cases, then run `pnpm backend:build`.
