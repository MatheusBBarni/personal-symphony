# ADR-003: Use Status-First Inspect Mode for the PRD

## Status

Accepted

## Date

2026-05-23

## Context

The PRD clarification selected faster diagnosis as the primary product success outcome. The operator should understand task, readiness, and attention state with fewer tab switches. The selected inspectable V1 surface includes all non-Logs Terminal Console tabs, with Tasks as the default starting surface when no Ordered Queue exists.

The user also identified work provenance and progress evidence as important inspect-mode content. During approach selection, the user chose the status-first product approach, which makes blockers, errors, remediation, and current state the first information layer while still allowing provenance and progress evidence as supporting detail.

## Decision

The PRD will use a status-first inspect mode. V1 inspection will lead with current state, blockers, errors, remediation, and next operator attention. Provenance and progress evidence remain included when relevant, but they follow the status layer instead of leading the view.

The approach applies to every selectable Terminal Console tab except Logs. Tasks remains the default starting surface when no Ordered Queue exists.

## Alternatives Considered

### Alternative 1: Unified Inspect Mode, Task-First

- **Description**: Make Tasks the primary scan surface and prioritize provenance and progress evidence in inspect mode.
- **Pros**: Strong fit for understanding work context and agent progress.
- **Cons**: Less direct for urgent diagnosis when blockers or remediation matter first.
- **Why rejected**: The user selected the status-first approach for the PRD.

### Alternative 2: Broad Terminal Console Detail Layer

- **Description**: Treat inspect mode as a broad detail layer across current and future panels.
- **Pros**: Highest long-term flexibility.
- **Cons**: Too broad for the PRD and risks turning a read-first surface into a larger dashboard redesign.
- **Why rejected**: V1 needs a bounded product outcome centered on faster diagnosis.

## Consequences

### Positive

- Operators see blockers, errors, and remediation before supporting detail.
- The PRD aligns success metrics with faster diagnosis instead of general richness.
- Provenance and progress evidence still serve trust and context without crowding the first layer.

### Negative

- Operators who primarily want work provenance may need to read past the first status layer.
- The PRD must be explicit that status-first does not remove progress evidence from V1.

### Risks

- Status-first content could overemphasize errors and make normal progress less visible. Mitigation: include progress evidence as supporting inspect content when no blocker exists.
- The approach could drift into action controls. Mitigation: keep V1 read-only and exclude lifecycle commands.

## Implementation Notes

- This ADR defines product behavior for the PRD only.
- The PRD should avoid prescribing implementation details and should describe the user-facing information order.
